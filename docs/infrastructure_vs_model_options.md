# 인프라 vs 모델 옵션

이 문서는 `클라우드`라는 말을 두 층으로 나눠서 정리합니다.

## 1. 인프라

인프라는 **어디에 서버를 둘지**의 문제입니다.

예:

- Oracle Cloud
- AWS
- GCP
- 온프레미스

인프라가 결정하는 것:

- 서버 위치
- 네트워크
- 저장소
- 배포 방식
- 운영 책임

## 2. 모델

모델은 **무슨 AI를 쓸지**의 문제입니다.

예:

- 규칙 기반
- 로컬 LLM
- 클라우드 LLM

모델이 결정하는 것:

- 추론 품질
- 응답 속도
- 비용 구조
- 데이터 통제

## 3. 흔한 혼동

- `클라우드 서버`는 인프라입니다.
- `클라우드 LLM`은 모델입니다.
- 둘은 같은 말이 아닙니다.

예를 들면:

- Oracle Cloud 위에서 OpenAI API를 호출할 수 있습니다.
- Oracle Cloud 위에서 로컬 LLM을 직접 돌릴 수도 있습니다.
- AWS 위에서도 같은 구조를 만들 수 있습니다.

## 4. 제품 설계 원칙

추천 구조는 다음과 같습니다.

- 인프라: 기본은 클라우드, 필요하면 온프레미스도 지원
- 코어 판정: 규칙 기반
- 설명/초안: 로컬 LLM
- 어려운 예외: 클라우드 LLM fallback

## 5. 기업에 제시할 때

기업에는 보통 이렇게 나눠서 제시하는 게 이해가 쉽습니다.

### 인프라 옵션

- 클라우드
- 온프레미스
- 하이브리드

### 모델 옵션

- 규칙 기반
- 로컬 LLM
- 클라우드 LLM

## 6. 한 줄 정리

인프라는 **서버를 어디에 둘지**, 모델은 **어떤 AI를 쓸지**의 문제다.
