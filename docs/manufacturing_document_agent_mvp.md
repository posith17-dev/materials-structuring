# 제조 문서 에이전트 MVP

## 한 줄 정의

시험성적서 PDF를 넣으면 핵심 수치를 구조화하고, 이상 여부를 표시하고, 리포트 초안까지 만드는 AI 직원.

## 왜 이걸 먼저 하냐

- 현장에서 반복 작업이 많다.
- 문서 형식이 제각각이라 사람이 다시 옮겨 적는다.
- 결과를 바로 검색/비교/축적하기 어렵다.
- 시험성적서와 COA는 수치, 단위, 기준값이 많아서 구조화 효과가 크다.

## 1차 범위

### 입력

- 시험성적서 PDF
- COA PDF
- 필요하면 HTML/TXT 추출본

### 출력

- 구조화 JSON
- CSV
- 사람이 읽는 짧은 리포트
- 이상값 표시

## MVP 흐름

1. PDF 또는 텍스트를 읽는다.
2. 표, 수치, 단위, 기준값을 뽑는다.
3. 필드를 정리해서 JSON으로 저장한다.
4. 기준값 초과, 누락, 단위 불일치를 표시한다.
5. 요약 리포트를 만든다.
6. 사람이 확인한 뒤 이메일/저장까지 넘긴다.

## 에이전트 역할

### Agent 1: 문서 파서

- PDF/HTML/TXT에서 표와 텍스트를 읽는다.
- 문서 단위로 블록을 나눈다.

### Agent 2: 데이터 정제

- 단위를 맞춘다.
- 값 형식을 정리한다.
- 누락 필드를 표시한다.

### Agent 3: 품질 판단

- 기준값과 비교한다.
- 이상값과 모순을 찾는다.

### Agent 4: 리포트 생성

- 핵심 결과를 요약한다.
- 사람이 바로 볼 수 있게 정리한다.

### Agent 5: 실행 연결

- DB 저장
- 파일 저장
- 이메일/알림 전송

## 무엇이 다른가

- 단순 파서가 아니라 판단까지 포함한다.
- 단순 리포트가 아니라 다음 행동까지 이어진다.
- 사람이 직접 표를 옮기는 일을 줄인다.

## 2차 확장

- 사양서 / 스펙 비교
- 품질 리포트 / 검사 보고서
- 정부 문서 / 입찰 서류

## 추천 순서

1. 시험성적서 / COA
2. 사양서 / 스펙 비교
3. 품질 리포트 / 검사 보고서
4. 정부 문서 / 입찰 서류는 별도 트랙

## MVP 성공 기준

- PDF 한 장에서 핵심 필드를 안정적으로 뽑는다.
- 이상값을 사람이 검토 가능한 수준으로 표시한다.
- 리포트가 자동으로 나온다.
- 같은 흐름을 다른 문서에도 재사용할 수 있다.

문서를 읽는 도구가 아니라, 문서를 처리하고 판단하고 다음 행동까지 준비하는 AI 직원이 목표다.
